# 04: Infra-fail taxonomy with model pinning and negative self-tests

**What to build:** The eval distinguishes "the model broke the protocol" from "the harness broke", and proves it without burning model calls. Model pinning: the runner passes an explicit `--model` to every pi process (never user defaults), stores the requested spec verbatim, extracts the actual provider/model from every assistant message, and fails as `infra-fail` on a requested/actual mismatch or a mid-session model change; both models are always printed in reports. Resource pinning: the exact flags, the hash of the generated workflow skill file, and the list of actually loaded resources are recorded in metadata, and any unexpected loaded resource is an `infra-fail`. Crash, timeout, missing JSONL and invalid JSONL are classified as infrastructure errors, never as protocol failures or passes. Negative self-tests feed synthetic sessions to the grader to prove detection of: a direct `cat` of the inbox, a direct write to runtime state, a modified fixture file, multiple/conflicting JSONL, a timeout, and a requested/actual model mismatch.

**Blocked by:** 02: Protocol harness, fixture and first end-to-end S1 run

**Status:** resolved

- [x] Every pi invocation carries an explicit model; requested spec and actual provider/model from all assistant messages are recorded in metadata

## Comments

Most of the taxonomy landed with tickets 02–03 (explicit `--model`, requested/actual gate, thinking gate, timeout/crash/JSONL-count gates, flags + SKILL.md hash in metadata, infra kept out of protocol rates). This ticket added the missing pieces in `evals/run.sh`:

- **Model gate extended:** the actual-model set now folds in `model_change` entries alongside every assistant message, so a mid-session change fails even when the new model produced no graded message. Mismatch and change both classify `infra-fail` with the observed models printed in the check line.
- **Loaded-resource pinning:** pi 0.84.2 session v3 has *no* dedicated resource entries (verified against pi's `docs/session-format.md`), so `grader_loaded_resources` pins the observable traces instead: `read` calls on `.agents/skills/<name>/` paths (progressive disclosure) and `custom`/`custom_message` entries (only extensions write those, and we pin `--no-extensions`). The gate (`unexpected_resources`) allows exactly `EVAL_PINNED_SKILL=two-pane-workflow` — the skill forced via `--no-skills --skill`; anything else is `infra-fail`. Metadata gains `loadedResources` as `{kind,name}` objects; synthetic fixtures F8/F9 pin the extraction shape so a pi format change fails loudly instead of grading nothing.
- **Violation-matrix self-tests:** one stub switched by a mode file proves, with zero model calls: requested/actual mismatch, mid-session model change, invalid JSONL, duplicate JSONL (missing-JSONL was already covered by the crash stub), direct runtime write (caught by the forbidden-path scan; helper send still required), fixture tampering (manifest check), unexpected extension entry and unexpected skill read (resource gate) — plus the pinned-skill read staying clean and recorded. Self-tests 82 → 111, `bash -n` + shellcheck clean.
- **Harness bug fixed (pre-existing from ticket 02):** the timeout watcher's multi-statement subshell, when killed, orphaned its `sleep` child — which inherits the caller's stdout pipe and blocks any command substitution for the whole timeout. Every stub run silently stalled up to 30s; the new violation runs pushed the self-test past its timeout. The watcher now redirects `>/dev/null 2>&1`; self-test runtime dropped to ~32s. Also fixed the self-test EXIT trap evaluating `TMP` after the function scope died (`rm -rf ''`), which leaked every temp dir — `TMP` is now deliberately non-local.
- **Live validation:** two real `protocol --main-model openai-codex/gpt-5.6-luna:high` runs. The second run passed all four scenarios; both runs' metadata record `loadedResources:[{kind:"skill-read",name:"two-pane-workflow"}]`. All four `tests/*.sh` still pass.
- **Reports:** every report names the requested model explicitly (`requested main-model:` in summary.txt, `requestedModel` in summary.json and per-run metadata). Protocol has a single requested model today; `baseline`/`economy` will print both `main=` and `expert=` when they land (tickets 05–07).
