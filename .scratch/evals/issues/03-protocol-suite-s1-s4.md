# 03: Full protocol suite S1–S4 with per-scenario aggregation

**What to build:** The complete protocol suite: `evals/run.sh protocol` executes all four scenarios — S1 send-empty, S2 send-busy (seeded occupied inbox), S3 take (expert FYI with marker), S4 not-yours (message addressed to the other role) — with their verbatim seeds and prompts stored in the runner, and grades each against its byte-exact assertions. S2 must prove the helper rejected the send (`inbox is not empty`) and left the seeded inbox byte-identical. S3 must prove a successful `take` consumed the message (empty inbox, no leftover consume state, no subsequent send) and the marker reached the final answer. S4 must prove the take reported the message as awaiting the other role, with the inbox preserved byte-for-byte. `--runs N` repeats every scenario from a fresh fixture each time (scenario-run independence), and the timestamp directory gains `summary.json`/`summary.txt` grouped by actual Main-model with passed/N, protocol failures and infrastructure failures per scenario. Overall exit is nonzero on any protocol-fail.
