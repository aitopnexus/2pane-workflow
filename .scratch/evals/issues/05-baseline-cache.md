# 05: Persistent Expert baseline cache and `baseline` command

**What to build:** `evals/run.sh baseline --expert-model <spec>` creates the one expensive direct-Expert reference run and caches it for reuse: an identical fixture (the two docs copied in), a single Expert-only pi session solving the fixed task with the "you are the only agent" mode instruction, graded by the same correctness assertions as the two-pane run. The result is published only after the actual model, JSONL integrity and answer assertions pass; a failed attempt stays in results but never becomes active. A fingerprint over eval-task/assertions version, baseline/grader format version, exact Expert spec including thinking level, pi version, prompt hash, fixture manifest hash, and flags/resources/tool-and-resource-content hashes decides validity — deliberately excluding the Main model (any cheap Main can reuse the baseline) and the raw git commit (only fixture-manifest changes matter). Re-running `baseline` with a matching fingerprint prints the existing ID and makes no model call; `--refresh-baseline` creates a new immutable baseline ID and atomically repoints the active marker, preserving all older baselines that past results still reference. Cache self-tests cover fingerprint stability across Main-model changes, invalidation across Expert/thinking/pi-version/prompt/fixture/resource changes, refresh-not-deleting, and no-publication-of-invalid.
