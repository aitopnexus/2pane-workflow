# 02: Protocol harness, fixture and first end-to-end S1 run

**What to build:** The first live tracer bullet: `evals/run.sh protocol --main-model <spec>` runs scenario S1 (send-empty) against a real pi session and grades it end to end. This means: the fixed eval workdir is safely rebuilt before each run (fresh copy of the current `2pane` helper, made executable, `./2pane init`); the scenario seed (empty inbox) is created and a manifest of all files outside the runtime state is recorded; concurrent runs are prevented by a lock; influencing environment variables are reset before each pi process; pi runs in print mode with an explicit `--model`, pinned flags, only the built-in tools allowed, and its own `--session-dir`, under a per-call timeout with trap-based cleanup and lock release. After the run, the artifact directory holds the pi log, session JSONL copies, prompt, seed, before-manifest, metadata (scenario, run, requested and actual model specs, timeout, pi version, git commit, exit status, timestamps) and a `checks.txt` of `ok -`/`not ok -` assertions ending in a pass/protocol-fail classification and matching exit code. S1's specific assertions all pass against a compliant run: a successful `./2pane send` bash call, a non-empty inbox starting `from: main` with the WAL/lock question in the body, no forbidden direct runtime access, no changes outside the runtime state, and a final answer that reports the send and stops.

Note: demoing this ticket requires the one-time human step of granting pi per-project trust to the fixed eval workdir (an interactive launch that creates no other artifacts).

## Comments

Implemented in `evals/run.sh` as the `protocol` subcommand; S1 lives in a small scenario registry so S2–S4 (ticket 03) slot in as data plus a checks function.

- **Live tracer bullet:** `evals/run.sh protocol --main-model openai-codex/gpt-5.6-luna:high` → 13/13 checks, classification `pass`, exit 0. The model read the generated SKILL.md (progressive disclosure), made exactly one standalone `./2pane send`, and its final answer reported the send; the fixture inbox ends with `from: main` + the WAL/lock question. Artifacts verified: pi.log, prompt.txt, seed-INBOX.md, before/after manifests, session.jsonl + sessions/, metadata.json (requested+actual model, thinking level, timeout, pi version, git commit, skill sha256, exact flags, env resets, timestamps), usage.json, checks.txt, summary.json/txt.
- **Skill loading deviates from the spec's trust bootstrap, deliberately.** Probes on this machine: with discovery on, pi loads 10 global package skills (context-mode, ponytail, …) and — without an interactive trust grant — does *not* load the project skill, so S1 would fail through no fault of the model; with a trust grant the global skills still leak in and every run would trip the spec's unexpected-resource infra-fail. The harness instead pins `--no-skills --skill <fixture>/.agents/skills/two-pane-workflow/SKILL.md`: exactly one skill on any machine, zero human steps, and identical model-visible behavior (skill description in the system prompt, read on demand). The fixed workdir path from the spec is kept. Consequence: the one-time per-project trust step mentioned in this ticket is *not* needed to demo — the spec's determinism goals (pinned flags, unexpected resource → infra-fail) are satisfied structurally. The exact flags, SKILL.md hash and session-dir land in metadata, so any drift shows up as a metadata diff.
- **Exit codes:** 0 pass · 1 protocol-fail · 3 infra-fail · 4 lock busy · 2 usage error (documented in `--help`). Infra conditions: pi exit ≠ 0, timeout, JSONL count ≠ 1, unparseable JSONL, requested/actual model or thinking mismatch — protocol checks are then skipped (comment line in checks.txt) so infra noise never masquerades as model quality.
- **Timeout/crash/lock proven without model calls:** self-tests drive the whole pipeline through stub `pi` binaries via `EVALS_PI_BIN` — compliant stub → pass; direct-`cat .2pane/INBOX.md` stub → protocol-fail with the right `not ok` lines; sleeping stub + `--timeout 2` → infra-fail, `timeout.marker` written, lock released, fixture intact; crashing stub → infra-fail; held lock → exit 4 with nothing graded. Plus fixture determinism (rebuild twice → identical manifests).
- Misc: `evals/results/` + `evals/baselines/` added to `.gitignore`; `--runs N` loops with a fresh fixture per repeat; second real invocation also passed (identical pristine start). Self-test suite: 55 checks (32 grader from ticket 01 + 23 new), zero model calls; shellcheck clean; all four `tests/*.sh` still pass.
